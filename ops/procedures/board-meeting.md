# Процедура: еженедельный совет директоров

Запускается по расписанию в понедельник в 08:52 (Минск). Ведёт **Секретарь совета** (эта сессия). Агентов вызывай инструментом Agent/Task по имени из `.claude/agents/`.

## Экономия лимитов (обязательно, тариф владельца — Pro)
- **Модели при вызове агентов.** Все агенты работают на Opus (решение владельца 16.11.2026). Если тип агента из `.claude/agents/` недоступен и ты вызываешь `general-purpose` с ролью из файла, указывай `model: "opus"`.
- **Отчёты отделов (шаг 2)** — только по отделам, у которых на прошлой неделе были задачи. Остальным — одна строка «задач не было».
- **Рабочий цикл (шаг 5)** — **не больше 3 отделов** за заседание: только те, чьи задачи входят в приоритеты недели. Остальные отделы ждут следующего совета.
- **Доработка у аудитора** — 1 круг. Второй — только для права и комплаенса и для текстов, которые уйдут заказчикам.
- Не перечитывай большие отчёты целиком: сначала разделы «Главное» и «Заключение аудитора».

Перед началом прочитай `CLAUDE.md`: там правила, запреты и протокол табло.

## 0. Подготовка
1. `git pull --rebase origin claude/nice-maxwell-zyutu6`.
2. Табло: прочитай `system/control`. Если `paused: true` — запиши в `runs` «Пропуск: система на паузе» и заверши.
3. Прочитай `agents`. Запомни, кто выключен (`active: false`): их не запускать.
4. Отметь `chief-of-staff` как `working` («Готовлю совет директоров»).

## 1. Сбор материалов (сам, без агентов)
- Что изменилось с прошлого протокола: `git log --since=<дата прошлого протокола> --stat`.
- Новые файлы в `reports/`, `ops/drafts/`, изменения в `ops/leads/leads.md`.
- Статус задач в `ops/tasks.md`.
- **Сообщения владельца** в `ops/inbox.md` (раздел «Новые»). Это приоритет № 1: каждое сообщение должно получить ответ или решение в протоколе. После обработки перенеси сообщение в раздел «Обработанные» с датой.
- Метрики воронки из `ops/leads/leads.md`: сколько лидов, сколько A/B/C, сколько в работе.

## 2. Отчёты отделов
Для каждого **включённого** отдела вызови его аудитора с заданием: «Оцени выполнение задач отдела за неделю по `ops/tasks.md` и файлам в репозитории. Ответ: выполнено / не выполнено / заблокировано, качество, что мешает, предложение на следующую неделю (1 задача с критериями приёмки)». Ответ — не длиннее 12 строк.

## 3. Заседание совета
1. **Председатель** (`board-chair`): по сводке из шагов 1–2 предлагает до 3 приоритетов компании на неделю и по одной задаче каждому отделу.
2. **Финансы и риски** (`board-cfo-risk`): оценивает предложения — деньги, время людей, санкционные и платёжные риски. Предлагает правки.
3. **Независимый критик** (`board-critic`): ищет слабые места, лишнюю работу, неверные допущения. Не больше 7 пунктов.
4. **Председатель:** окончательное решение с учётом замечаний.

Если председатель выключен — решений нет, протокол содержит только сводку и вопросы владельцу. Если выключен другой член совета — пропусти его шаг и отметь это.

## 4. Протокол `ops/board/ГГГГ-ММ-ДД.md`
Структура:
```
# Совет директоров — ДД.ММ.ГГГГ

## Главное для владельца (≤ 5 строк)
## Что нужно от владельца (решения, ответы, действия) — списком
## Итоги прошлой недели по отделам
## Решения совета (приоритеты недели)
## Задачи отделам (с критериями приёмки)
## Риски и сигналы (санкции, платежи, рынок)
## Метрики (воронка, контент, сайт)
## Ответы на сообщения владельца из ops/inbox.md
```

## 5. Рабочий цикл отделов
Для **не больше 3 включённых** отделов из приоритетов недели, кроме «Поиск заказчиков» (у него своё расписание):
1. Аудитор формулирует задачу недели из протокола: что сделать, где сохранить, критерии приёмки. Табло: аудитор `working`.
2. Исполнитель выполняет. Табло: исполнитель `working`, аудитор `review`.
3. Аудитор проверяет. Если не принято — 1 круг доработки (максимум 2). Табло: оба `idle` с итогом.
4. Результат сохраняется в репозиторий (`reports/` или `ops/drafts/`), статус задачи — в `ops/tasks.md`.

Ограничение: одна задача на отдел за заседание. Если задача большая — разбей и сделай первую часть.

## 6. Завершение
1. Обнови `ops/tasks.md` (статусы, новые задачи, «нужно от владельца»).
2. Табло: все задействованные агенты `idle` с итогами; `chief-of-staff` — «Совет проведён»; документ в `runs`: `doc_id` = `ГГГГ-ММ-ДД-board`, заголовок «Совет директоров», 1–2 предложения итога, ссылка на протокол.
3. Коммит «Совет директоров ДД.ММ.ГГГГ: протокол и результаты отделов» и push.
4. Последнее сообщение сессии: 5–8 строк для владельца — главное, что нужно от него, ссылка на протокол.
