# Процедура: поиск потенциальных заказчиков

Запускается по расписанию во вторник и четверг в 09:52 (Минск). Участники: **Охотник за заказчиками** (`lead-hunter`) и **Аудитор лидов** (`lead-auditor`). Ведёт эта сессия.

Перед началом прочитай `CLAUDE.md`: правила, запреты, протокол табло.

**Модели:** агенты `lead-hunter` и `lead-auditor` работают на Opus (решение владельца 16.11.2026). Если эти типы недоступны и ты вызываешь `general-purpose` с ролью из файла, указывай `model: "opus"`.

## 0. Подготовка
1. `git pull --rebase origin claude/nice-maxwell-zyutu6`.
2. Табло: `system/control`. При паузе — запись в `runs` «Пропуск: система на паузе», конец.
3. Табло: `agents`. Если `lead-hunter` выключен — запись в `runs` «Пропуск: охотник выключен», конец. Если выключен только `lead-auditor` — работай, но все новые лиды помечай «не проверен аудитором».
4. Прочитай `ops/leads/README.md` (профиль заказчика, источники, оценка), `ops/leads/leads.md` (во избежание дублей), последний протокол в `ops/board/` (приоритеты недели: какая ниша и регион сейчас в фокусе).

## 1. Поиск (lead-hunter)
Табло: `lead-hunter` → `working`, задача «Ищу заказчиков: <ниша>, <регион>».

Задание охотнику: найти **10–15 новых** кандидатов по приоритету недели. Для каждого заполнить поля из `ops/leads/README.md`, обязательно со **ссылкой на источник сигнала**. Результат — черновик таблицы в ответе (в файл пока не писать).

## 2. Проверка (lead-auditor)
Табло: `lead-hunter` → `review`, `lead-auditor` → `working`.

Аудитор проверяет каждого кандидата:
- компания реальна (сайт открывается, деятельность совпадает);
- сигнал подтверждается источником;
- подходит под профиль заказчика;
- нет дубля в `leads.md`;
- **санкционная проверка**: поиск на opensanctions.org (`https://www.opensanctions.org/search/?q=<название>`) и по новостям; гражданская деятельность;
- оценка A / B / C по критериям из README.

Отклонённых — в отчёт с причиной, в таблицу не вносить.

## 3. Запись
- Принятых добавить в конец таблицы `ops/leads/leads.md` (статус «новый»).
- Сводку запуска — в начало раздела «Журнал запусков» в `ops/leads/leads.md`: дата, ниша и регион, найдено / принято / отклонено, 1–2 вывода (где лучше искать).

## 4. Завершение
1. Табло: оба агента `idle` с итогом («+N лидов: A — x, B — y»); документ в `runs`: `doc_id` = `ГГГГ-ММ-ДД-leads`, заголовок «Поиск заказчиков», итог, ссылка на `ops/leads/leads.md`.
2. Коммит «Поиск заказчиков ДД.ММ.ГГГГ: +N лидов» и push.
3. Последнее сообщение сессии: 3–5 строк — сколько найдено, лучшие 3 лида и почему.

**Никаких контактов с компаниями.** Письма пишет отдел продаж (черновики), отправляет человек.
